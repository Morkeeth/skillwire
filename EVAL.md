## Blind human review, separate from automated checks

`lime_human_review.py prepare --run RUN --files app.py test_app.py --context input.json --out NEW_DIR` snapshots selected UTF-8 artifacts only after both native CLI records completed and both graders executed. Optional context files come from the identical starting fixtures, so a reviewer can assess output against task facts. It randomizes A/B and writes a browser bundle with task and artifact text, plus a separate withheld key with condition mapping and automated grades. The bundle contains no condition label or check result. The reviewer loads it locally in the product, chooses A, B, tie or cannot judge, gives a reason, and saves a local verdict. `reveal` checks the bundle/key binding and maps the choice only after the verdict exists. This is local and unauthenticated; the reviewer can inspect the withheld key if given access, so the operator must keep it separate. A manual artifact mode exists for interface checks and is labelled unverified model execution. The WebKit interface test used a synthetic, hand-authored pair; no independent human preference has been collected.

The Lime native pilot is one separate 8/8 tie. Neither is a quality preference. Human choices are recorded alongside, not substituted for, deterministic checks.
